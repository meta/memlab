Tool Reference

The server has about 150 tools, grouped by the question they answer. Each page below lists one group, with a line on when to use each tool. Find a Tool​

You don't need to know tool names: describe what you want to find out, and the assistant picks a tool. To browse, ask the assistant to call memlab_tools:

  • With no arguments, it prints every tool by group, with when to use it.
  • With question (for example "growing", "retained" or "artifact"), it lists the groups that match.
  • With tool, it finds the tool's group. Add schema: true to print the tool's parameters.

From a shell, memlab-cli schema <tool> prints a tool's parameters (see Command Line).

Expose Fewer Tools​

Every tool the server exposes takes up room in the assistant's context, and most investigations use a few dozen. Start the server with MEMLAB_TOOLSETS set to a comma-separated list of groups, such as core or core,growth,retention, to expose only those, plus the few tools every session needs. memlab_tools({enable: "<group>"}) turns on more groups during a session.

core is a set of everyday tools: summaries, class histograms, largest objects, references and referrers, retainer traces, detached DOM, snapshot diffs and memlab_eval. The other group names are on each group's page.

What Every Tool Accepts​

These conventions hold across the tools:

  • Any snapshot, without switching. A tool that reads one snapshot takes an optional snapshot: a loaded snapshot's handle, or a .heapsnapshot path loaded for that call only.
  • Sizes. Every byte-size filter takes a number of bytes or a size such as "1MB" or "500KiB" (KB is 1000 bytes, KiB is 1024).
  • Paging. Ranked lists end with "Showing a–b of N … Next page: offset: k". Pass offset for the next page. Ties are broken by node id, so a given offset always shows the same rows.
  • Shorter output. memlab_snapshots with max_name_length clips node names in every tool for the rest of the session, and table_format: "csv" prints tables as compact CSV.
  • Terse mode. memlab_snapshots({terse: true}), or MEMLAB_TERSE=1 at startup, makes every tool keep only headings, tables, verdict and warning lines, finding bullets and code. It drops explanatory notes, long prose, suggested next steps and the orientation menu, and prints tables without alignment padding. On one round this cut the leak report, detached DOM and listener reports together from about 15.5 KB to 6.6 KB.
  • JSON reports. memlab_leak_report, memlab_detached_dom, memlab_event_listener_leaks and memlab_react_update_queues take format: "json": the report as sections of tables (numeric cells parsed), verdicts, bullets and text, ready to pass to a script.
  • Structured results. The main list and lookup tools also return structuredContent: the same rows as JSON, with raw byte counts, the filters that applied and a pagination object, so a client can use the results without parsing tables.
  • Forgiving parameter names. A tool refuses a parameter it doesn't declare, and names the closest one it does. A few common names are read as the one they mean, and the reply says so: for example path and snapshot_path as file_path or snapshot, snapshots as paths, and id as node_id.
